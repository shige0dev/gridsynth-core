# RF モジュールによるゲート遅延・トリガディレイ活用ガイド

`v1.0.0818` 〜 `v1.0.0820` の改変により、`RF`（Rise / Fall）モジュールは従来のエンベロープ／終端トリガ生成に加えて、**二重立ち上がりの起きない安全なゲート遅延・トリガディレイ** として使えるようになりました。

---

## 1. 仕様変更の概要（v1.0.0818〜0820）

- **ゲート幅スルー（`trig_in` ➔ `trig_out`）**
  - `trig_in` の立ち上がり（`> 0.3`）を検知した瞬間に `time`（および `time_cv`）の遅延時間をラッチします。
  - Rise + Fall の時間経過後、**`trig_in` に入力されたゲート幅（長さ）をそのまま維持したまま `trig_out` へ出力**します（短いトリガなら短いトリガ、長いゲートなら長いゲートが出ます）。
  - ケーブル未接続時の手動トリガ（`TRIGGER` メッセージ）のみ、従来通り FALL 完了時に 2ms パルスを出力します。
- **フィードバック暴走防止（`MIN 1` クランプ）**
  - `trig_in`・`cv_out`・`trig_out` に上限 `1.0`（`Math.min(1.0, ...)`）のクランプを適用し、フィードバック結線時のハウリング／振幅増大を防止しています。
- **OUT ピン上下反転**
  - `trig_out`（オレンジ）を上段、`cv_out`（イエロー）を下段に配置変更しました。

---

## 2. なぜ `LAG` ではなく `RF` を使うのか

| モジュール | 方式 | 得意な用途 | ステップごとに `time_cv` を変えた場合 |
| :--- | :--- | :--- | :--- |
| **`LAG` (`CVDELAY`)** | 連続値リングバッファ（`readPos = writeIndex - delay`） | 連続 CV（1V/Oct 等）やオーディオの遅延 | 遅延時間が急に増えると読み出しヘッドが過去へ戻り、**二重立ち上がり**が起きる場合がある |
| **`RF`** | 立ち上がりエッジ検知＋遅延時間ラッチ（エッジ予約） | **ゲート／トリガの遅延**、グルーブ（もたつき）生成 | 立ち上がり時に遅延時間が確定するため、**二重立ち上がりせずゲート幅も保たれる** |

---

## 3. 基本の使い方

### パターン A：トリガディレイ／ゲート遅延（もたつき・後ろノリ）
シーケンサのダイアログを増やさず、特定トラックや特定ステップだけを後ろにズラします。

1. `SEQ.gate_out` ➔ `RF.trig_in`
2. （任意）別レーン CV / LFO ➔ `RF.time_cv`
3. `RF.trig_out`（上段） ➔ ドラム音源 / `ADSR.gate_in`

> [!NOTE]
> `RF` は `0ms`（`0.0s`）から設定可能です（`0ms` 時は `cv_out` が `0` になり、`trig_in` が遅延なしで `trig_out` へスルーします）。また、`time_cv` 結線時は内部の `TIME` 設定値が無効化され、外部 CV のみで遅延時間が決まります。

### パターン B：任意のゲート長を再生成する（`cv_out` + `MATH2`）
入力トリガの長さに関係なく、`RF` で設定した時間だけの矩形ゲートを作りたい場合に使います。

1. `SEQ.gate_out` ➔ `RF.trig_in`
2. `RF.cv_out`（下段） ➔ `MATH2.cv_in_a`
3. `MATH2` のモードを `>` にし、`B = 0.01` に設定 ➔ `MATH2.cv_out` をゲートとして使用

さらに **「遅延時間」と「ゲート長」の両方を CV 制御したい場合** は、次のように 2 段構成にします。

- `RF1`（遅延担当）：`trig_in` ➔ `time_cv`（もたつき量） ➔ `RF1.trig_out`
- `RF2`（ゲート長担当）：`RF1.trig_out` ➔ `RF2.trig_in`、`time_cv`（ゲート長） ➔ `RF2.cv_out` ➔ `MATH2(> 0.01)`
